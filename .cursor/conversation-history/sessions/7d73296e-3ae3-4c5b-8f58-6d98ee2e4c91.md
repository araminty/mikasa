## [2026-06-07T17:33:33Z] assistant (afterAgentResponse)

You were right about the root cause. Dendry’s `go-to` collects **every** branch whose `if` predicate is true (or has no `if`). If exactly one matches, it navigates there; if **more than one** matches, it **picks randomly**; if none match, it stays and shows choices.

A single branch like `main if has_event = 0` leaves `has_event = 1` with no matching branch, which can fall through oddly. The fix is explicit, **mutually exclusive** branches — same pattern as `root.scene.dry` and `game_over.scene.dry`:

```dry
go-to: main if has_event = 0; events_choice if has_event = 1
```

**Don’t use `1 = 1` as a catch-all** alongside another branch — both would match and Dendry would randomize. An unconditional fallback (like `advance.scene.dry`’s `; advance_month`) only works when it’s the sole match for that case.

Changes in `post_event.scene.dry`:

1. **Two-branch `go-to`** — skip to `main` when there’s no event, go to `@events_choice` when there is.
2. **`@events_choice` subscene** — month/year heading and `#event` deck moved here (matches the pattern in your dendry docs).
3. **Blank line after `@events_choice`** — required; without it Dendry treats the `=` heading as a property and the build fails.
4. **Event detection** — `has_event` now checks choices on `post_event.events_choice` instead of the parent scene.
